Your agent needs your user's GitHub access, not an admin token. Here's how that works 👇

→ Inbound auth decides who can call the agent. Outbound auth decides what it can reach for that user
→ The user signs in, approves one provider, and the token is stored for that user only (session binding)
→ Every tool call then runs with that user's permissions, nothing more
→ Use the smallest scopes that work, and give users a way to revoke access
→ Never paste tokens into prompts or logs

AWS added a managed Consent portal to AgentCore Identity for exactly this, aimed at agents used from Kiro, Claude Code, Cursor and VS Code. Tokens land in the AgentCore Identity token vault.
