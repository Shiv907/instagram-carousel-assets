Your redactor sees half an SSN. It reads "123-", then "45-6789", and never sees the full number.

AgentCore Gateway can now run your response interceptor on a streaming response. In STREAM mode your Lambda gets batches of events, and the client gets each batch as soon as you return it. You can change or drop each event's data, so you can strip sensitive data while the text is still streaming.

Here's the catch, and it's right there in the docs' own example: text can split across events and across batches. "my SSN is 123-" lands in one event, "45-6789" in the next. Check each event on its own and you match neither.

What the docs say:

1. STREAM mode applies to HTTP and inference targets.
2. maxEventsPerInvocation is required.
3. Each invocation is limited to 30 s and 6 MB.
4. One output per input event. You can change data, not the event name.
5. "There is no ID that links the invocations of one response."
6. Check the joined text of neighbouring events, and redact a partial match at the end of a batch.

My take: the batch boundary is part of your redaction logic, not an edge case. If you've only tested with whole sentences, you haven't really tested it.

One community idea, not in the docs: also mask a leading fragment of the next batch. The cost is that a harmless batch starting with 2026 gets masked too.
