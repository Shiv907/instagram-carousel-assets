Your agent searches company docs for a user. Who decides which user?

If the search tool takes "who to search as" as an argument, the LLM decides. One prompt injection and it searches as someone else.

AWS published a pattern for Bedrock Managed Knowledge Base behind AgentCore Gateway. The rule: don't let the LLM decide who the user is.

How it works:
1. A request interceptor (Lambda) overwrites userContext from the validated JWT
2. ACL awareness returns only documents that user may view
3. A Cedar policy denies the call if userContext.userId doesn't match the token's email
4. A resource-based policy denies every principal except the gateway role

Gotcha: ACL mistakes don't throw errors. Documents are silently left out of results.
